# 员工全周期与档案

## 任职状态

业务建议状态为：待入职 → 试用 → 在职 → 离职办理 → 已离职；转正、调岗、续签是任职事件，不应抹掉原始记录。脚本的简化快照只支持 `probation/active/left`；不要强行把“离职办理”映射成已离职。

## 入职

按到岗前、当日、第一周、试用中期分组：岗位与入职时间确认、必要材料清单、合同待签、设备账号申请、制度告知、导师与目标约定、培训、反馈。只检查用户提供的材料是否存在，不自动查验身份或背景。账号创建/群通知只能输出申请清单，除非另有覆盖具体动作的授权和工具。

## 转正和调岗

转正：目标约定 → 过程证据 → 员工总结 → 主管评估 → 人事复核 → 审批 → 沟通和记录。到期提醒不等于审批完成；无实际绩效证据不能编造“表现优秀”。

调岗：原/新岗位、部门、任职生效日、汇报关系、薪酬变化、交接、协商确认、审批和档案更新。历史部门分析必须使用有效期事件，不用当前部门回填过去月份。

## 合同与离职

合同提醒区分缺失、即将到期、当天到期、已过期；无固定期限或特殊用工的空到期日需人工分类。脚本当前对空到期日提示确认，不判违法。

离职：收到意向/申请 → 确认类型和日期 → 交接计划 → 资产/账号/费用清单 → 工资结算待复核 → 文件与材料 → 留存。输出责任人、期限、状态、证据链接，不能把勾选清单当作已执行。赔偿补偿、解除理由或争议需结合事实、地区和有效法规审核；缺少依据时不套固定倍数。

## 台账质量

员工编号为关联主键，姓名不作为唯一键；重复编号、离职早于入职、状态与日期冲突阻断计算。姓名、部门、岗位、用工类型等缺失生成待补项。返聘、多主体、多合同使用任职周期编号，不能直接去重丢记录。提醒报告按员工编号展示，原始资料保持原位不覆盖。
